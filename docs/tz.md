# ТЗ: Воксельная песочница «мир-как-функция»

Рабочее название: **kb** (произносится Kubyte — куб + байт; пишется строчными, моноширинным).
Цель: идеализированная реинкарнация Minecraft Beta 1.7.3 — по геймплейной сути, но спроектированная так, будто её писали на спор: всё процедурное, всё детерминированное, минимум кода, минимум памяти, работает везде.

---

## 1. Философия проекта (нерушимые принципы)

1. **Мир — это функция.** `состояние = generate(seed) + diff_log`. Ничего не хранится, если может быть вычислено.
2. **Данные вместо кода.** Блоки, текстуры, звуки — это параметры-дескрипторы, которые интерпретирует один универсальный генератор. Новый блок = строка в таблице, не функция.
3. **Детерминизм бит-в-бит на всех платформах.** В генерации мира и текстур — НИКАКОГО float. Только целочисленная / fixed-point математика. Один сид = одинаковый мир на Windows, Linux, Android и в WASM.
4. **Ноль ассетов.** В дистрибутиве нет ни одного файла текстур, звуков, моделей. Всё синтезируется при старте из параметров.
5. **Минимализм без фанатизма.** Меньше кода, меньше зависимостей, но не ценой читаемости. Никаких игровых движков, никаких обёрток типа Electron/WebView.

## 2. Технический стек

- **Язык:** Rust (edition 2021+)
- **Графика:** wgpu (один рендер-бэкенд на все платформы: Vulkan / Metal / DX12 / WebGPU / WebGL2-fallback)
- **Окно/ввод:** winit
- **Сериализация:** postcard или bincode (компактный бинарный формат)
- **Async/сеть (сервер):** tokio + quinn (QUIC); для WASM-клиента — WebSocket
- **Целевые платформы (один репозиторий):**
  - `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`
  - `aarch64-linux-android` (cargo-ndk + GameActivity, без Kotlin-кода)
  - `wasm32-unknown-unknown` (wasm-bindgen + wasm-opt)
  - iOS — отложено; iOS-пользователи играют через браузер (Safari: WebGL2/WebGPU)
- Зависимости держать на минимуме; каждый новый крейт обосновывать.

## 3. Архитектура (модули)

Workspace из крейтов. Ядро не знает о рендере и платформе.

```
/core      — мир, блоки, физика, тики (без I/O, без графики, компилируется и в сервер, и в клиент, и в WASM)
/worldgen  — детерминированный генератор (integer noise: value/perlin на fixed-point)
/materials — дескрипторы материалов + универсальный генератор текстур
/render    — wgpu: меши, texture array, камера
/platform  — winit-обвязка, ввод (клавомышь / тач / геймпад), точки входа per-platform
/net       — транспорт-трейт + реализации (QUIC, WebSocket), протокол
/server    — headless-бинарник поверх /core
```

## 4. Мир и хранение

- **Чанк:** 16×16×128 блоков.
- **Хранение в RAM — палитры:** локальная палитра чанка + N бит на блок (4 бита при ≤16 материалов). Однородные чанки (весь воздух / весь камень) — одна запись, ноль массивов.
- **Чанки = кэш, не хранилище.** Вышел из зоны видимости — выгружается без записи (если нет правок). Понадобился — перегенерируется из сида (< 1 мс).
- **Правки игрока — дифф-лог:** разреженная структура `позиция → block_state` (~8–10 байт на правку). Чанк при загрузке = generate(seed, pos) + наложение диффов. Фоновое уплотнение лога (схлопывание перезаписей, RLE областей).
- **Сейв = сид (8 байт) + версия генератора + сжатый дифф-лог.** Цель: активный мир < 100 КБ.
- **Фича: мир-в-URL.** Экспорт сейва в base64-строку, импорт по ссылке (в первую очередь для веб-версии).
- **Версионирование генератора:** номер версии хранится в сейве; старые версии генератора остаются в коде навсегда. Менять формулы можно только новой версией.

## 5. Материалы и текстуры (процедурные)

- Никаких спрайтов. Текстура = функция `(дескриптор, seed) → 16×16 RGBA`.
- **Дескриптор материала (~16–24 байта):** палитра (2–4 цвета из курируемого набора), тип шума (зернистый / пятна / cellular), масштаб, амплитуда вариации, оверлей (полосы / рамка / кольца / крапинки), параметры акцентов (цвет + вероятность — так делаются руды поверх камня), опциональный блок `animation` (тип: scroll / frames / live-noise / sway, скорость).
- **Анимация — слоями, по цене:** (1) анимация текстур из дескриптора (вода, лава); (2) вершинная анимация в шейдере по id материала (покачивание листвы/травы) — чанк-меш статичен, ремеша нет; (3) блоки-сущности: блок временно вынимается из чанк-меша и рендерится инстансом (падающий песок, двери, частицы разрушения из мини-вокселей своей текстуры); (4) compute-эффекты — опциональное украшение, не работает на WebGL2-fallback, игра обязана быть полноценной на слоях 1–3. Анимация — чисто визуальный слой и НИКОГДА не влияет на симуляцию (исключение: падающий блок — это сущность в /core).
- **Грамматика с инвариантами** (чтобы блоки читались глазом): вариация яркости внутри блока ≤ ±15%, верх травы светлее боков, функциональные блоки (верстак, печь, ТНТ) имеют обязательную рамку/«морду». «Рисуночные» блоки — крошечные битмапы-паттерны как массивы индексов палитры прямо в коде.
- Генерация при старте в один texture array (80 материалов × 16×16 ≈ 80 КБ). Фиксированный сид → одинаково у всех.
- **Особые блоки (уникальный паттерн):** block_state = id материала + variant_seed.
  - Базовый режим: 4 бита варианта (16 предгенерированных вариантов на материал) — хранится прямо в id, без доп. структур.
  - Редкий режим «именной блок»: полный u32-сид, хранится в разреженной карте чанка; в инвентаре предмет несёт `{id, variant}`; паттерн нигде не сохраняется как пиксели — только сид. Рендер: динамические слоты texture array с LRU-кэшем (≈256 слотов).
  - **Защита от инфляции уникальности:** именные блоки НИКОГДА не крафтятся и не дублируются (сид варианта выдаётся только генерацией мира; сервер валидирует происхождение); частота — исчезающе редкая (порядка 1 на тысячи чанков). Находка = событие.
  - **Постамент:** блок-витрина для демонстрации именных блоков (подсветка, видно других игрокам). Хвастовство как механика.
- **Звуки** — тем же принципом: sfxr-подобный синтез из параметров при старте.

## 6. Рендер

- Greedy meshing (слияние соседних одинаковых граней в квады).
- Упакованная вершина: позиция-в-чанке + нормаль + материал/слот в одном u32 (максимум двух).
- Frustum culling по чанкам; ремеш только грязных чанков, в фоне.
- Простое освещение в духе беты: skylight + blocklight, распространение flood-fill по воксельной сетке, значения в палитро-хранилище чанка.
- **Цветное освещение как носитель атмосферы:** skylight ночью — холодный (синеватый лунный свет, мир выцветает), blocklight — тёплый (янтарь факелов/печки). Эффект «дом милый дом» = контраст температур: тёплое жилище в холодной ночи. Плюс туман дистанции с лёгкой десатурацией дали и ночи темнее ванильных. Вся «приятная тревога» строится этими тремя инструментами рендера, без скримеров и спец-элементов.
- Никакого float-детерминизма в рендере не требуется — он чисто визуальный.
- **Ретро-пайплайн (пикселизация):** мир рендерится в offscreen-буфер пониженного разрешения и растягивается на экран nearest-neighbor блитом. Это одновременно эстетика («лесенки», крупный пиксель) и оптимизация (буфер 1/3 экрана = в ~9 раз меньше фрагментной работы — запас для мобильных/браузера и дистанции прорисовки).
  - **Pixel scale — настройка:** ×1/×2/×3/×4. Растягивание ТОЛЬКО в целое число раз (integer scaling), иначе пиксели разной ширины и картинка «плывёт».
  - **UI и текст — в нативном разрешении** поверх пикселизованного мира (опция «всё в пиксель» — для желающих).
  - **Дизеринг:** квантование цвета (~15–16 бит) с Bayer-матрицей во фрагментном шейдере блита; опция, включена по умолчанию. Градиенты неба/ночи рассыпаются в зерно — ключевой носитель атмосферы §14.
  - **Мипмапы:** генерируются из процедурных текстур; переключатель «аутентичное кипение дали» (мипмапы выкл.) — по умолчанию выключен.
  - **НЕ делать:** вершинный воббл PS1 (на статичных вокселях читается как баг); раздельную пикселизацию слоёв — мир, туман и небо идут через один общий буфер, иначе зернистость слоёв разойдётся.

## 7. Геймплейный объём (паритет с Beta 1.7.3, по сути)

- Выживание: здоровье, голод НЕ нужен (его в 1.7.3 не было), инструменты, прочность, крафт 2×2 и 3×3, печка, сундуки.
- Генерация: биомы (простая температурная/влажностная карта), пещеры (integer 3D-noise / черви), руды по высотным слоям, деревья, вода/лава (клеточный автомат как в оригинале).
- Мобы: минимальный набор (зомби, скелет, крипер-аналог, свинья/овца), простейший ИИ (поиск пути по сетке, агро по дистанции).
- День/ночь, спавн мобов по освещённости.
- Тикрейт: 20 Гц, симуляция в /core.
- Дизайн блоков/мобов — «в духе эпохи», но ВСЕ визуальные данные свои (копирование ассетов и текстур Mojang запрещено).

## 8. Мультиплеер

- Авторитарный сервер (headless-бинарник из /core + /net).
- Транспорт за трейтом: `send_reliable / send_unreliable / recv`.
  - Нативные клиенты: QUIC (quinn).
  - WASM-клиент: WebSocket (TCP — приемлемо для 20 Гц); WebTransport добавить позже как третью реализацию того же трейта.
- **Сервер не шлёт чанки.** Клиент генерирует ландшафт сам из сида; сервер шлёт только дифф-лог зоны, сущности и события.
- Валидация на сервере: скорость движения, дистанция взаимодействия, доступность блока. Клиент в браузере считается скомпрометированным по умолчанию.
- Кросс-плей: один сервер обслуживает десктоп, Android и браузер одновременно.

## 10. Анти-скоуп (НЕ делать)

- Никаких игровых движков (Unity/Godot/Bevy) и WebView-обёрток.
- Никаких файлов ассетов и форматов ресурспаков (ресурспак = другой набор дескрипторов).
- Никакого float в worldgen и генерации текстур.
- Никакого моддинг-API наружу до стабильного ядра — но архитектура под него закладывается с M0 (см. §11): данные через таблицы, мутации мира только через дифф-лог.
- Не использовать чужую музыку и мелодии (включая каверы/MIDI-перенаборы) — только собственные композиции через свой синтез (см. §14).
- Никакого рейкастинг-рендера вокселей (идея в коробке «когда-нибудь», базово — меши).
- Не копировать ассеты/текстуры/звуки Mojang.

## 11. Моддинг (отложенный, но заложенный)

API наружу не открывается до стабильного ядра, но архитектура строится модопригодной с первого дня — иначе потом придётся перелопачивать всё.

- **Контент-моды = таблицы данных.** Все игровые сущности (материалы, рецепты, биомы, параметры мобов) загружаются из таблиц (RON/TOML), встроенные и внешние таблицы мерджатся одним загрузчиком. Мод с новой рудой — это текстовый файл, ноль кода.
- **Дескрипторы едут по сети.** При коннекте сервер шлёт клиенту полный набор дескрипторов (килобайты) — клиент сам генерирует все модовые текстуры/звуки. Вход на модовый сервер без скачиваний, в т.ч. из браузера.
- **Логик-моды (будущее) = WASM-модули.** Исполнение: wasmtime на нативных платформах, нативно в браузере. Песочница обязательна (мод не имеет доступа к ФС и сети). Детерминизм сохраняется.
- **Поверхность API — злобно маленькая:** горстка хуков (`on_tick`, `on_block_break`, `on_interact`, `on_entity_spawn`); единственный способ менять мир — отправка правок в тот же дифф-лог, которым играет игрок. Моды исполняются только на сервере; клиенты получают обычные диффы.
- **Дисциплина против кучи кода:** фича = записи в таблицах, которые читают немногие общие механизмы (загрузчик таблиц, генератор текстур, дифф-лог, интерпретатор рецептов, проигрыватель хуков). Новые механизмы под отдельные фичи не плодить.

## 12. Редактор материалов (встроенная утилита)

Инструмент для авторинга дескрипторов — чтобы не жить в цикле «поправил число → пересобрал → посмотрел».

- **Это редактор дескрипторов с холстом, НЕ пиксель-арт редактор.** Слева холст 16×16: рисование индексами палитры материала (для «рисуночных» блоков — паттерн, поверх которого генератор кладёт шум и вариацию). Справа — слайдеры всех полей дескриптора, включая анимацию.
- **Живое превью:** сетка из 8–16 вариантов блока с разными сидами, отрендеренных настоящими кубами с освещением; обновление на каждое изменение.
- **Выход — код, не файлы.** Кнопка «копировать как код» кладёт в буфер готовую запись таблицы (RON/Rust). Источник истины — таблица в репозитории; у утилиты нет собственного формата сейвов, всё её творчество видно в git-диффе как обычные строки.
- **Реализация:** крейт в том же workspace, UI на egui поверх wgpu; импортирует тот же крейт /materials — превью и игра считаются одним кодом, расхождение невозможно по построению. Работает и как WASM-страница в браузере (в будущем — готовый инструмент для моддеров).
- **Режим в игре:** та же панель открывается горячей клавишей в дебаг-сборке — правка дескриптора с видом на блок прямо в мире.
- Бюджет: ~300–500 строк поверх egui. egui — обоснованная зависимость только для дебаг/редактор-сборок, в релизный клиент не входит.

## 13. Этапы

1. **M0 — скелет:** workspace, winit+wgpu окно на десктопе и в WASM, один крутящийся куб с процедурной текстурой. Ретро-пайплайн (offscreen-буфер + nearest-блит, §6) закладывается СРАЗУ — весь дальнейший рендер идёт только через него; дизеринг и настройки scale — позже (M4).
2. **M1 — мир:** integer-noise генератор, палитро-чанки, greedy meshing, полёт камерой по бесконечному миру. Замер памяти и времени генерации против бюджетов.
3. **M2 — материалы:** таблица дескрипторов (через загрузчик таблиц — задел под моддинг), генератор текстур, texture array, редактор материалов из §12 (панель + холст + превью вариантов + экспорт кода).
4. **M3 — игра:** коллизии, ломание/установка, дифф-лог, инвентарь, крафт, сейв/загрузка, мир-в-URL.
5. **M4 — жизнь:** освещение с температурой света (§6), туман, день/ночь, вода/лава, мобы, выживание; анимация слоёв 1–3 из §5 (текстуры, вершинная, блоки-сущности); генеративный эмбиент и базовый синтез звуков.
6. **M5 — Android:** cargo-ndk сборка, тач-управление (виртуальный стик), тест на Adreno.
7. **M6 — онлайн:** сервер, QUIC + WebSocket, дифф-синхронизация, валидация, кросс-плей.
8. **M7 — особые блоки:** варианты, именные блоки с LRU-слотами и правилами редкости (§5), постамент; первые структуры-руины (§14).

Каждый этап завершается замером против бюджетов из §9. Превышение бюджета = баг.

## 14. Атмосфера, лор и звук (видение)

**Тон: «приятная тревога», дарк-фентези без крика.** Не хоррор с монстрами из-за угла, а мир, в котором немного не по себе — и именно поэтому хочется обустроить и не покидать своё тёплое место. Тон фиксируется с первого дня, потому что управляет палитрами материалов, дизайном мобов и звуком.

- **Носители тревоги — только рендер и звук** (см. §6: температура света, туман, тёмные ночи). Никаких джампскейров, спец-сущностей и скриптовых сцен.
- **Лор — энвайронментальный сторителлинг.** Никаких катсцен и текстов. Генератор изредка размещает детерминированные структуры-руины, которые «неправильные»: дома без дверей, слишком глубокие колодцы, обелиски из недоступного в крафте материала. Историю игрок складывает сам. Структуры = функция от сида, как всё остальное. Детальный дизайн истории — после альфы; тон — сейчас.
- **Музыка и звук — свои, процедурные.** ЗАПРЕЩЕНО использовать или переаранжировать мелодии Minecraft (включая перенабор по MIDI другими инструментами — мелодия защищена как композиция независимо от инструментов). Вместо этого: собственные секвенции нот как данные (таблицы) + свой синтезатор; основа саундскейпа — генеративный эмбиент, зависящий от глубины, биома и времени суток; мелодии — редкие гости, тишина — основной инструмент.

## 15. Отложенные идеи (после альфы, не делать сейчас)

- **Аномальные миры:** часть правил мира (гравитация, цвет неба, плотность руд и т.п.) как параметры сида — опциональная настройка при создании мира. На альфе сид меняет только рельеф.
- **Живой мир:** клеточные автоматы среды (распространение огня, зарастание, эрозия). На альфе мир статичен, пока игрок не взаимодействует.
- **Культура мира-в-URL:** миры-открытки, лента «мир дня» и т.п. На альфе URL — просто формат сейва/шаринга.
- **WebTransport** как третий транспорт; **нативный iOS**; **рейкастинг-рендер**; **открытие моддинг-API наружу**.

## 16. Инструкция для ИИ-реализации (метa)

- Реализовывать строго поэтапно по §13, не забегая вперёд.
- На каждом этапе: минимум зависимостей, обоснование каждого крейта, код с комментариями «почему», а не «что».
- Любое решение, нарушающее §1 (принципы) или §10 (анти-скоуп), — отклонять и предлагать альтернативу.
- При неоднозначности выбирать вариант с меньшим количеством кода и состояния.
- Детерминизм проверять тестом: одинаковый сид → одинаковый хеш чанка на native и wasm32.
